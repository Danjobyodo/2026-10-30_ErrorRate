## 2. `switch_in_boundary` の ideal と noisy は何が違うか

### 2.1 何をしているか

- `ideal`: switch-in の d ラウンドの直後、**U の直前**に、無雑音の $Z$ チェックと無雑音の dressed X チェックを 1 ラウンド置きます。その完全なシンドロームでフラックスを閉じ、電荷を後始末します。したがって **U は（論理誤りを除けば）完全な D4 符号状態に作用**します。
- `noisy`: その完全ラウンドを置きません。
  - JIT が未来に回したフラックス（X 誤り）は、補正されないまま U に入ります。
  - 電荷は、最終層が未来境界で終われる復号器で推定して後始末します。

### 2.2 「Code Switching 自体の性能評価が目的なら、ideal のままでよいのでは？」について

半分は正しく、半分は注意が必要です。Gemini の指摘はもう少し別の問題を指しています。

**ideal が測っているもの。** 「switch-in の論理失敗」と「switch-out（と後続の誤り訂正）の失敗」を、**U の位置で理想的に切り離した和**です。switch-in と switch-out をそれぞれ独立なガジェットとして評価し、その間を理想化した境界でつないでいます。メモリ実験を最後の完全ラウンドで終えるのと同じ考え方なので、ガジェットごとの性能を比べる基準としては筋が通っています。この意味でのご理解は正しいです。

**ideal では見えなくなるもの（Gemini の指摘の中心）。** 実際の装置では、U の直前に無雑音の測定はできません。U が作用する時点で、データには「まだ見つかっていない誤り」が必ず残っています。

- 残った X 誤り（フラックス）が U の非クリフォード部分 W（CS・T†）を通ると、S/CZ 型のクリフォード誤り（Z 誤りのコヒーレントな重ね合わせ）に変わります。
- 残った緑の電荷は、V を通って赤・緑・青に広がります（$e_g\to e_{rgb}$）。

これは「U を挟むこと」に固有の、**Code Switching 方式そのもののコスト**です。ideal ではこれが構造的にゼロになります（v1 の診断でも、ideal では U 由来の S 型位相の事象が 0 でした）。研究目的が「性能・コスト・実用性の評価」である以上、このコストは評価の対象に含まれるはずです。ideal だけで結論を出すと楽観的になります。

**その差は小さくありません。** v1 の試行計算（同じプロトコル・厳密エンジン、`in_T_out`）では次のとおりでした。

| p | d=3 ideal | d=3 noisy | d=5 ideal | d=5 noisy | d=7 ideal | d=7 noisy |
|---|---|---|---|---|---|---|
| 0.8% | 0.0105 | 0.0262 | 0.0005 | 0.0118 | <0.0003 | 0.0053 |
| 1.2% | 0.0267 | 0.0568 | 0.0057 | 0.0315 | 0.0035 | 0.0257 |
| 1.8% | 0.0630 | 0.1255 | 0.0272 | 0.1190 | 0.0190 | 0.1192 |

- 交点は ideal で約 3.2%／2.3%、noisy で約 1.9%／1.8% です。
- noisy では有効距離が約 1 下がります（v1 レポート §6）。

**ただし noisy が「物理的に正しい答え」でもありません。** noisy の劣化には 2 つの成分が混ざっています。

- (i) U を挟むことの本来のコスト
- (ii) 現在の復号器が、U の前後で復号窓を切り離していることによる損失（両レビューの指摘②）

現在の noisy は、この復号器を使った場合の、**実際の性能に対して悲観側の値**です。

**まとめ。** 実際の性能は、おおむね ideal（楽観側の基準）と現在の noisy（悲観側）の間にあり、どこに来るかは U をまたぐ復号の工夫次第です。研究では、両方を並べて示し、それぞれの意味を明記するのが適切です。v3 ではそのために `boundaries_to_run=["ideal","noisy"]` を用意しました。既定値は `ideal` のままです（v1・v2 の結果と直接比べられるように）。実用性を議論するときは `noisy` も必ず計算してください（計算時間は 2 倍になります）。

### 2.3 レビューのうち v3 で採用しなかったもの

- **Gemini ②-1（JIT の最終ラウンドで未来境界を閉じる）**: 指摘の事実は正しいです。$w_t<w_s$ なので、最終ラウンドに起きた境界上の単一 X 誤りや長さ 2 の X 鎖は「保留」のまま U に入ります。
  - しかし、未来境界を閉じるとどうなるかは単純ではありません。最終ラウンドの測定誤りも「データ誤り」として補正してしまい、その誤補正（X）が同じように W を通って非 Pauli 化します。
  - 残った X 誤りは U の後の surface code の復号窓（第 0 層）で拾われます。保留と即時補正のどちらが得かは、U をまたいだ窓の設計と一体の問題です。
  - どちらに決めても「論文に書かれていない復号器の設計」を一つ追加することになるので、今回は手を入れていません。
- **Gemini ②-2・ChatGPT 2（U をまたぐ復号窓）**: これが noisy の劣化を減らす本筋の改善です。
  - 赤・青の電荷のシンドロームは U の後も続きます。ただし U は緑の電荷を $e_{rgb}$ に写すので、通しの時空グラフには緑の情報も入れる必要があります。
  - これは「修正」ではなく新しい復号器の研究なので、v3 には入れていません（§6 の今後の課題）。
- **Gemini ②-3、問題点③、ChatGPT 6（単発 $Z^g$ 測定、U と補正ゲートが理想、$P_L$ の定義、コストの範囲）**: どれも正しく、コードの誤りではなく前提の明記の問題です。v1・v2 の README に既に書いてあり、§6 にも再掲しました。

## 6. 使い方（v2 からの差分）

1. `CHSC_switch_v3_main.ipynb` を Colab（CPU ランタイム）で開き、上から実行します。インストールは `stim` と `pymatching` だけです。
2. `CFG` で v2 から変わったキー:

| キー | 意味（既定値） |
|---|---|
| `boundaries_to_run` | None → `switch_in_boundary` だけ。`["ideal","noisy"]` で両方を計算して比較図も作る |
| `out_dir` | `chsc_v3_results` |

3. 分割実行の例（Colab のセッション時間が足りないとき）:
   - 1 回目は `d_values=[3,5]`、2 回目は `d_values=[7]` を、同じ `out_dir` で実行します。
   - 同じ条件なので同じ CSV に追記され、図と交点は d=3,5,7 全体から作られます。
   - **セッションをまたぐ場合は、1 回目の zip を Cell 10 でダウンロードし、2 回目の前に Colab の `out_dir` に戻してください**（ランタイムのファイルは切断で消えます）。
4. 出力: `chsc_v3_<case>_<ideal|noisy>.csv / .png / .pdf / _frames.png / _crossings.csv / _manifest.json`。3 ケースでは `chsc_v3_all_cases_<boundary>.png`、両方の境界では `chsc_v3_ideal_vs_noisy.png` も出ます。CSV には `conditions`（計算条件）と `confidence_level` の列が加わりました。
5. 所要時間は v2 と同じです（`in_T_out` で d=3: 約 0.9 ms、d=5: 約 3 ms、d=7: 約 11 ms／ショット）。既定 1 ケースで約 40 分、`["ideal","noisy"]` ならその 2 倍です。
6. 正当化ノートブックを最後まで実行し、`VALIDATION PASSED` と表示されることを確認してください。

## 7. 今後の課題（v2 から変わらないもの）

1. **U をまたぐ復号窓**: noisy の劣化を減らす本筋の改善です（§2.3）。緑の電荷の $e_{rgb}$ への置換を扱う必要があります。
2. **circuit-level 雑音**（TBW Algorithm 2）: dressed チェックの測定回路を決める必要があります。
3. **雑音の前提**: U・緑の補正 $S^g_X(\lambda)$・初期化・最終読み出しは理想、switch-out の $Z^g$ 測定は単発です。
4. **$P_L$ の定義**: $P_L$ は「最終状態が目標状態そのものか」で判定するマジック状態準備の失敗率で、入力 $\lvert+\rangle$ 固定です。任意入力に対する論理 T ゲートの誤り率や平均 infidelity とは別の量です。`in_only` の $P_L$ は flux_D4 を失敗に含む保守的な値です。
5. **コストの範囲**: CPU 時間は古典シミュレーションの時間で、量子計算機上のコスト（補助量子ビット数、測定回路深さ、復号遅延）ではありません。
6. **交点は記述的な推定**です。閾値の議論には d≥9 と、交点付近のショット数の追加が必要です。
